# Offers

Release 1.2.0 lets a seller create a durable personal offer from one eligible, consented recommendation preview. The server reads the preview's product, original integer-HUF price, rule reason and evidence identifiers; the browser cannot supply or override those values. The only mutable creation inputs are a whole-percent discount and an expiry no more than 30 days ahead. Seller pricing guardrails validate the percentage before price calculation.

The commercial snapshot stores the lowest price observed in the preceding 30 days. Evidence includes the catalog price effective when the window began, every revision inside the window and the current catalog price. The discount base is the lower of the current catalog price and that comparison price, so creating an offer cannot turn an existing lower price into an increase. The evidence window, calculation time and matching catalog revision versions remain attached to the offer. A catalog version change invalidates an older recommendation preview.

Offers are unique per seller, creator and client request ID. Repeating a creation request returns the original snapshot, rather than issuing another offer. An offer is linked to the seller/buyer conversation when one exists and updates that conversation's pending-offer count. It also writes a delivery outbox row. Without an approved transport provider the row is `unsupported`, not sent; its selected recommendation channel is an authorization gate and audit fact, not delivery evidence.

Only the targeted buyer with an active seller relationship can respond. A response compares the supplied version with the pending record and uses server time for expiry. The same decision is retry-safe; a competing decision, stale version or expired offer is rejected. An accepted offer issues one single-use DiscountDirect redemption coupon. A flash-campaign offer also creates an atomic DiscountDirect inventory reservation when accepted. Neither path claims payment, delivery or fulfillment. Accepted, unexpired offers may request a signed, tenant-bound, single-use checkout hand-off. The server freezes the accepted HUF price, limits the token to at most 15 minutes and requires a healthy seller connector. Token replay, expiry and missing adapters fail without changing the accepted offer. Provider-specific checkout creation is supplied by the Shoprenter and UNAS adapter slices; until one is healthy the buyer sees an honest unavailable state.

Use `POST /api/sellers/{sellerSlug}/offers` to create from `{previewId, productId, discountPct, expiresAt, clientRequestId}`, `GET /api/offers` for the buyer inbox, `POST /api/offers/{offerId}/respond` with `{expectedVersion, decision}` and `POST /api/offers/{offerId}/handoff` to mint the short-lived redirect. Every mutation uses the existing cookie session and same-origin validation.
